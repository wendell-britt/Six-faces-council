# Jev asset trial: first run

Run 2026-10-14, once on the 30 practice rows, then once on the frozen 19 scoring rows. The mark in `mark_2026-10-14.md` was not changed. Answers are in `run_practice_answers_2026-10-14.json` and `run_scoring_answers_2026-10-14.json`. Source: bars-engine main at 1885d16.

## Scoring pile (19 rows): passes the mark

| Measure | Result | 95% interval |
|---|---|---|
| Catches (flags both positives) | 2 of 2 (AS-011, AS-032) | true rate plausibly 16% to 100% |
| False flags on agreeing rows | 1 of 17 (AS-002) | plausibly 0.1% to 29% |
| Cannot tell | 0 | |

- AS-011: `src/actions/assets.ts:12-13` enforce 5 MB and 10 MB, but the client-upload route sets `maximumSizeInBytes: MAX_PDF_BYTES` for every type (`src/app/api/assets/upload/route.ts:109`), so images can reach 10 MB there.
- AS-032: hex colors sit outside `card-tokens.ts`, for example `#0a0908` in `NowHome.tsx:66`.
- AS-002 (the false flag): the doc writes `{filename}`; the local fallback writes `file{ext}` (`assets.ts:95-98`) and the Blob key is `assets/{id}{ext}`. Marked low confidence at the time. It is a real but small difference, so it may deserve a label flip rather than count as noise.

Two positives cannot show a catch rate. A pass means the model found the two known disagreements without burying them in noise. It does not mean the model is reliable on unseen docs.

## Script baseline (same 19 rows)

`constant_baseline.py` (written for this run; deterministic, no model, never sees labels) pulls paths, sizes, identifiers and routes out of each doc line and looks them up in the code.

- Catches 0 of 2. It misses AS-011 and AS-032 (a numeric constant that exists in code and a hex rule are both invisible to a lookup).
- False flags 3 of 17: AS-006, AS-036, AS-064.
- Model flagged that the script did not: AS-011, AS-032, AS-002. Script flagged that the model did not: AS-006, AS-036, AS-064.
- So the model catches something the script misses, which was the bar in `jev-asset-beat-script`. Whether the trial "earns its place" is the board's call.
- Caveat: I wrote the script after reading the pile statements, and it is crude. A better script might catch more, and its numbers are indicative only.

What the answers look like: one sentence each, a file:line, and a stated limit when the model could not check something (image sizes, backend-held values).
