How the Council Works

The six faces in practice: what happens when you call them, where everything lives, which places can reach them, and what a Claude mod would add. Written 2026-10-02 and updated the same evening, after the council moved to a repo of its own.

The short answer. The council is a skill: a set of written instructions plus one data file, faces.yaml, that Claude reads when you ask for the six. Both now live in one home repo, wendell-britt/six-faces-council. Five project repos carry the council, and each one copies the latest skill and definition from the home whenever a Claude Code session opens there. Those sessions need nothing from you. Ordinary chats and the desktop and mobile apps read the skill only after you upload it to your claude.ai account, and the rebuilt package is ready.

What the council is made of

No server runs and no agent sits waiting. The council is five pieces, and Claude reads them when you call it.

One home, every repo

The council repos are bars-engine, friendcraft, flirtcraft, root-game and emotional-first-aid, plus the home itself. A change reaches all of them in three steps.

  1. Claude, after your ruling
    A new lesson or a changed lens is written into faces.yaml in the home repo and nowhere else. A pass in another repo that earns a lesson records it as pending, and a script in the home collects it.
  2. The session, on opening
    When a Claude Code session opens in any council repo, a small script runs before anything else. It fetches the definition, the skill, the voice lint and itself from the home, then prints one line, such as Six-faces council: up to date with wendell-britt/six-faces-council@main. 2 face lessons.
  3. The session, if GitHub is out of reach
    The script keeps the copy the repo already has and says it could not reach the home. The session still works.

Each repo keeps its own ledger, term list and glossary, because those record that project's decisions. Only the shared files travel.

To add a repo, run python3 council/install.py <path to the repo> from the home, then commit and merge the new files there. From its next session on, it updates itself.

Tested 2026-10-02: a brand-new session on emotional-first-aid printed the line above with no setup. A brand-new session on root-game loaded the skill, ran a full pass on the hands task, sent you no questions, and kept the Architect's dissent on record. That pass is merged.

One pass, step by step

  1. You, in chat
    Ask in a Claude Code session on any council repo, or in any chat once the skill is uploaded. Plain words work: get the six on this, let the faces weigh in, run a term pass. Chat is where you give context and steer.
  2. Claude
    Claude loads the skill, reads faces.yaml, and gathers evidence: files, logs, past rulings. Each face argues from its lens and carries its lessons. The Sage synthesises, lists the dissent, and decides nothing.
  3. Claude
    Before any question reaches you, Claude tries to answer it from the record. A question gets through only if the answer is your preference or a fact only you hold, and only if it changes what gets built.
  4. Claude
    The pass is written as a file beside what it is about. Positions and real questions go onto the board. The chat reply is what changed and a link.
  5. You, on the board
    Flip a position you disagree with, answer a question, rename or retire a term, or type a steer. Save each row. This works from your phone.
  6. Claude, next time you write
    Tell Claude you saved. Claude reads the board, writes a ledger record, and turns any overrule or steer into a lesson for that face, quoted exactly, in the home repo. Adopted terms go into the repo's glossary as proposed, with a decision-log entry. The next pass in every repo carries all of it.

A real case

You asked for flirtcraft's failing deploys as a test. Claude traced the cause in the build log. Vercel's installer blocks Prisma's setup script, so the database client never got built and the type check failed. Claude reproduced the failure exactly, proved a one-line fix, and ran the tests. The six then argued what the fix ships: the live site was from August 31, and 50 commits waited behind the broken build. Five positions needed nothing from you. One question did, because only you could see the production settings: when to merge. The fix is merged, and the live site builds again.

The intake form is still unchecked. It needs the database address and the email service keys in Vercel's production settings, and Claude cannot read those settings.

Making it reach everywhere

Now: upload the rebuilt skill to your account

The rebuilt package is attached in chat as six-faces-skill.zip. Upload it at claude.ai, under Settings, then Customize, then Skills. If you uploaded the earlier package, replace it, because the earlier one reads its live copy from bars-engine, which no longer receives new lessons. The package holds a copy of the skill written for places with no repo, plus today's faces.yaml. Without a repo, a pass ends with a short record block that a repo session pastes into the ledger later.

The upload is a snapshot, with one exception. Where the chat can fetch a web address, the skill reads the current faces.yaml from the home first and says which copy the pass used, so new lessons arrive on their own. The instructions themselves stay as uploaded. When they change, run python3 council/package_skill.py in the home repo and upload the new file.

Later: a connector, if the snapshot becomes a problem

A connector added at claude.ai, under Settings, then Customize, then Connectors, reaches chats, the desktop app and Claude Code, and it reads the live files. It needs a server on a public web address with sign-in. The first pass deferred it until a second person needs the council. It is also the fix if re-uploading feels like a chore.

What a Claude mod would add

A mod is a plugin that runs inside Claude Code itself. It can add commands, draw panels, watch what Claude does, and register agent types. For the council it could do six jobs.

  • A /six command that starts a pass, and /terms for a term pass.
  • Six real agents. Each face becomes its own agent type with its own prompt and its own model. Running the Challenger on a different model from the other five is the published fix for faces sharing one blind spot.
  • The board as a side panel beside the conversation, so you flip and answer without leaving.
  • A line above the prompt that says when questions are waiting for you, such as 2 questions on the board.
  • Lessons in every session. The faces' lessons would be added to Claude's instructions automatically, even when you never call the six.
  • A guard on the definition file that refuses edits to faces.yaml unless they come from your ruling.

The limit matters for how you work. A mod runs in Claude Code on your own computer: the terminal, the desktop app's Code tab, or an editor. Cloud sessions at claude.ai/code, where this conversation runs, do not load plugins from a computer or from a repo's settings. An organization admin can provision them for everyone. So a mod would help most if you start using Claude Code locally. For the web sessions you use now, the uploaded skill does the job.
